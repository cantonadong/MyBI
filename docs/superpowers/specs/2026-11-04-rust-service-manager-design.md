# MyBI Rust + Slint 服务管理窗口

## 已确认目标

- 仅重做服务管理程序，使用 Rust + Slint，显示正常的 Windows 桌面窗口和任务栏图标。
- 报表界面继续使用现有 React + ECharts，数据和 Python 后端保持兼容。
- 运行时由 Rust 直接启动 Python/Uvicorn，不调用 PowerShell，不改变安全软件或系统策略。

## 方案

已选择原生服务管理窗口；不迁移报表界面到 Slint。完整迁移需要重写图表和拖拽编辑器，不符合此次范围。

## 窗口与行为

- 使用现有 MyBI 图标；标准窗口支持最小化，并出现在任务栏。
- 显示服务状态、固定本地地址和错误信息；紧凑按钮：启动服务、停止服务、打开 MyBI。
- 启动管理窗口时自动启动服务；打开报表由按钮交给默认浏览器。
- 实现建议：关闭窗口保留服务，避免中断浏览器中的报表；用户通过停止服务按钮明确停止。无需系统托盘或 Windows 注册服务。
- 服务仅监听 127.0.0.1:8000；优先使用 runtime/python.exe，开发环境回退 .venv/Scripts/python.exe。
- 通过现有 /api/health 核实项目路径和 PID，复用本项目的已有服务，拒绝接管其他服务或终止无关进程。
- 启停和健康检查不阻塞界面；保留启动超时、退出错误和 data/logs 日志。
- 文案复用共享中英语言字典；读取现有语言设置，无法获得设置时跟随系统语言。

## 交付范围

- Rust 项目、Slint 窗口、Windows 图标资源及最小可运行的回归检查。
- 更新现有构建、run.bat、发布打包及 README，移除旧 C# / PowerShell 运行链的依赖。
- 保留现有未跟踪的 scripts/build-selfsigned.ps1，不擅自覆盖或删除用户文件；旧流程不再作为正式构建入口。
- 直接在 main 工作；依用户要求不运行测试。执行构建及静态核查，报告实际结果。

## 限制

Rust 可执行文件仍可能被终端安全策略拦截；此次改造不构成 CrowdStrike 放行保证。不会创建自启动项、安装系统服务、修改防护配置或迁移用户数据。
